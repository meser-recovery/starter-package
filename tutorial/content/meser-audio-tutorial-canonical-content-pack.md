# PART A · Approved Final Russian Narration

# Часть 1. Зачем появились новые возможности

Привет. Позвольте представить вам несколько новых возможностей для служащих, доступных на сайте Мэсэр в соответствующем разделе.

На сайте Мэсэр собрана полезная информация и материалы для членов сообщества. Кроме того, в разделе «Для служащих» находятся дополнительные инструменты, доступные служащим группы Мэсэр, например Google Диск и Google Календарь.

Теперь к ним добавились инструменты, связанные с записью и обработкой спикерских собраний.

Как вам известно, наша группа ведёт запись спикерских собраний, которые проходят в Zoom.

Обычно после собрания запись нужно подготовить: отредактировать начало и конец, по возможности устранить проблемы, связанные с разницей в громкости голосов участников, убрать мешающие частоты, после чего готовая запись добавляется на сайт «Нам по пути».

Для человека, знакомого с обработкой аудио, такая работа обычно не представляет большой сложности. Но для обычного пользователя она практически недоступна без специальных программ и определённого опыта.

Кроме того, эта же запись используется анонс-мейкером, который прослушивает спикерскую, выделяет основные мысли и готовит короткое текстовое резюме для анонса.

При этом анонс-мейкеру приходится прослушивать довольно длинную двуязычную запись целиком, стараясь игнорировать голос оригинала, который занимает половину времени записи. С таким подходом тратится гораздо больше времени и теряется фокус внимания.

Учитывая недостатки нынешнего подхода, на портале Мэсэр появились две новые функции, которые значительно упрощают эти два процесса.

Для анонс-мейкера появилась возможность значительно сократить длительность записи за счёт того, что в её конечной версии остаётся только голос переводчика.

А для подготовки финальной версии спикерской появились простые инструменты редактирования, которыми сможет пользоваться служащий даже без опыта работы в профессиональных программах для обработки звука.

Обе новые функции доступны в разделе «Редактирование аудио»: «Анонс-мейкер» и «Спикерская».

Чтобы понять, как работают новые функции, важно упомянуть об одной полезной возможности Zoom.

Для нашей задачи важно различать два варианта записи Zoom.

Оба режима доступны как при записи Zoom на компьютер, так и при записи в облако, доступной в учётной записи Zoom.

В первом режиме запись производится одним общим аудиофайлом, в котором слышны все участники.

Во втором режиме звук участников сохраняется на отдельных дорожках: например, отдельно спикера, переводчика и других участников. Начало и конец каждой дорожки синхронизированы между собой по времени.

Запись в режиме отдельных дорожек для каждого участника даёт несколько важных преимуществ.

Например, для подготовки анонса можно использовать только дорожку русского переводчика.

Спикер и переводчик обычно говорят по очереди, поэтому, оставляя только дорожку переводчика, мы услышим длинные участки тишины — это фразы спикера, которые не попали в дорожку переводчика. Их можно автоматически сократить и получить гораздо более короткую запись, которую гораздо удобнее слушать из-за уменьшения времени записи и отсутствия второго языка. Анонс-мейкер, владеющий ивритом, может совершить обратный процесс, выбрав в конечной записи только дорожку спикера.

Раздельные дорожки также будут полезны при подготовке финальной версии спикерской, которая будет сохранена на сайте «Нам по пути».

У одного участника звук может быть слишком тихим, у другого — слишком громким. На одной дорожке может появиться гул, кашель или посторонний шум.

Когда звук всех участников находится в одном общем файле, исправить проблемы, связанные с одним участником, не затронув звук остальных участников, значительно сложнее.

При раздельной записи каждую дорожку можно обрабатывать отдельно: улучшить звук конкретного участника, выровнять громкость или убрать помеху только там, где она появилась.

Если в запись попал ненужный участник, его дорожку можно исключить из готовой версии.

Если проблема относится сразу ко всей записи — например, произошла техническая проблема, остановка спикерской, переводчик временно отключился, ненужный участок времени можно убрать одновременно на всех дорожках.
Таким образом, запись Zoom с использованием отдельных дорожек для каждого участника становится основой для двух новых инструментов редактирования.

# Часть 2. Работа в «Редактировании аудио»

Итак, у нас имеется запись собрания в виде отдельных дорожек для каждого участника.

Мы их можем взять с того устройства, на котором производилась запись (например, тот самый компьютер, где запись была активирована), либо из облачного хранилища Zoom, доступного для владельца учётной записи.

Если же кто-то до вас уже загрузил запись в Аудиоархив на портале Мэсэр, вы можете воспользоваться ей без надобности самим загружать файлы. Этот вариант будет подробнее показан в третьей части.

После выбора дорожек нам доступны два режима: «Анонс-мейкер» или «Спикерская».
Давайте сперва рассмотрим режим «Анонс-мейкер».
Здесь мы можем выбрать дорожки, которые нам понадобятся для подготовки анонса. В самом простом случае это дорожка одного русского переводчика.
Если же переводчиков двое и больше — например, один переводит саму спикерскую, а второй вопросы и ответы, — нам понадобятся все доступные дорожки переводчиков.

Перед обработкой их также можно прослушать и проверить.

Функция Solo, обозначенная английской буквой S, позволяет прослушивать только ту дорожку, где эта функция активирована, а функция Mute, обозначенная буквой M, позволяет отключить звук соответствующей дорожки. Обратите внимание, что на конечный результат эти функции не влияют. Они существуют только для удобства прослушивания при редактировании. Если даже одна из дорожек не воспроизводится из-за нажатого Mute, она всё равно попадёт в конечный обработанный файл.
Если вы ошиблись и добавили ненужную аудиодорожку, её можно удалить, использовав кнопку со значком X.
Если нужная дорожка была удалена по ошибке, можно воспользоваться кнопкой «Закрыть работу», а затем снова открыть режим Анонс-мейкера, используя кнопку «Открыть анонс-мейкер». В этом случае все изначально выбранные дорожки записи будут доступны.

После выбора нужных дорожек кнопка «Обработать запись» запускает обработку.

В процессе обработки происходит следующее: алгоритм автоматически находит длинные участки, где на всех выбранных дорожках одновременно присутствует тишина, и сокращает их, оставляя небольшой естественный промежуток между фразами.

Если в этот момент хотя бы на одной дорожке есть сигнал, этот участок не сокращается.

После обработки выбранные дорожки объединяются в один готовый файл.

Если при обработке были выбраны не те дорожки — например, нужная дорожка отсутствовала или была добавлена лишняя, — можно применить необходимые правки и запустить обработку снова. В результате будет создан новый готовый файл.

По завершении процесса файл доступен к скачиванию в виде MP3. Кроме того, вы можете сохранить его в архиве портала, где он будет привязан к данной записи и будет доступен для скачивания позже — вами, либо другими служащими.

## Спикерская

Теперь рассмотрим второй режим — «Спикерская».

Он предназначен для подготовки полноценной финальной записи собрания, которая затем может быть размещена на сайте «Нам по пути».

В этом режиме все выбранные дорожки остаются отдельными на протяжении всей работы и объединяются только при создании готового файла.

Благодаря этому мы можем отдельно работать со звуком каждого участника.

Для каждой дорожки доступны три вида обработки: улучшение звука, выравнивание громкости и компрессия.

Функция улучшения звука помогает ослабить низкий гул и лишние высокие частоты.

Выравнивание громкости полезно в тех случаях, когда один участник записан заметно тише или громче остальных.

Компрессия уменьшает разницу между тихими и громкими фрагментами речи в рамках одной и той же дорожки. Для неё можно выбрать лёгкую, среднюю или сильную степень обработки.

Все эти настройки доступны отдельно для каждой дорожки.

Как и в режиме «Анонс-мейкер», здесь доступны функции Solo и Mute.

Они работают точно так же: Solo позволяет при прослушивании оставить только выбранную дорожку, а Mute — временно отключить её звук.

И здесь эти функции также влияют только на прослушивание и не изменяют конечный результат.

Но в режиме «Спикерская» появляется ещё одна важная возможность.

Если какая-то дорожка вообще не должна попасть в готовую запись — например, это дорожка случайно подключившегося участника, — её можно исключить из финального микса.

В отличие от Mute, такое отключение уже влияет на конечный файл: звук этой дорожки не попадёт в готовую спикерскую.

При этом сама исходная дорожка не удаляется. Если решение изменится, её в любой момент можно снова вернуть в финальный микс.

В режиме «Анонс-мейкер» ненужную дорожку мы просто убирали из числа доступных дорожек. В «Спикерской» она остаётся частью проекта, но её можно включать или исключать из конечной записи.

Все дорожки расположены на общей временной шкале и синхронизированы между собой по времени.

Для удобства работы каждой дорожке можно назначить свой цвет, а также изменить порядок их расположения на экране. Это не изменяет их положение во времени и не нарушает синхронизацию.

При необходимости рабочую область можно развернуть на весь экран.

Для более точной работы с записью можно изменять горизонтальный масштаб временной шкалы: увеличить его, чтобы подробнее рассмотреть небольшой участок, или уменьшить, чтобы увидеть большую часть записи.

Кнопка «Вписать» возвращает всю запись в доступную ширину.

Этот же регулятор можно переключить в режим изменения высоты дорожек. Это удобно, если нужно разместить на экране больше дорожек одновременно или, наоборот, сделать их крупнее.

При минимальной высоте дорожек часть элементов управления скрывается, чтобы освободить место на экране. В частности, становятся скрыты ползунок компрессии и индикаторы уровня громкости. При увеличении высоты дорожек эти элементы снова отображаются.

При включённой функции Follow экран автоматически перемещается вслед за текущим местом воспроизведения.

А функция Loop позволяет выделить нужный участок и прослушивать его по кругу. Это удобно, когда один и тот же фрагмент нужно несколько раз проверить перед редактированием.

Все эти функции предназначены для удобства просмотра и прослушивания записи и сами по себе не изменяют готовый аудиофайл.

Теперь перейдём непосредственно к монтажу записи.

Для удаления ненужных фрагментов доступны два инструмента: «Вырезать» и «Тишина».

Здесь важно соблюдать порядок действий: сначала выбирается нужный инструмент, а затем прямо на форме звуковой волны отмечается фрагмент, который нужно обработать.

Если ненужный участок относится сразу ко всем дорожкам — например, произошла техническая остановка собрания или появилась длинная пауза из-за проблем со связью, — выбирается инструмент «Вырезать».

После этого нужный фрагмент отмечается на любой из дорожек. При отпускании кнопки мыши этот участок будет вырезан одновременно со всех дорожек.

Обратите внимание, что фрагмент, выделенный этой функцией, вырезается не только из готовой версии, но и из воспроизведения в редакторе.

Если же проблема присутствует только на одной конкретной дорожке — например, там слышен посторонний разговор или другой мешающий звук, — используется инструмент «Тишина».

В этом случае фрагмент отмечается непосредственно на той дорожке, звук которой нужно убрать. На остальных дорожках этот участок остаётся без изменений.

Начало и конец готовой записи задаются отдельно.

На звуковой волне находятся два маркера — «Начало» и «Конец».

Чтобы изменить границы готовой записи, достаточно перетащить соответствующий маркер в нужное место.

Всё, что находится до маркера «Начало» и после маркера «Конец», не попадёт в готовую версию спикерской.

После создания выреза или участка тишины его границы можно изменить прямо на временной шкале, захватив соответствующий край выделения.

Если требуется более точное редактирование, точные значения границ можно также указать вручную с помощью числовых полей.

Чтобы отменить вырез или тишину, нужно сперва выбрать соответствующий выделенный фрагмент. При этом кнопка «Вырезать» становится кнопкой «Снять вырез», а кнопка «Тишина» — кнопкой «Снять тишину», в зависимости от того, какой фрагмент был выбран.

После нажатия соответствующей кнопки эта правка снимается.

Кроме того, доступны функции «Отменить» и «Повторить», позволяющие вернуться на шаг назад или снова применить отменённое изменение.

После завершения монтажа можно создать готовый файл, нажав кнопку «Создать финальную версию».

Редактор применит все выбранные настройки обработки и сделанные правки, исключит ненужные дорожки и объединит остальные в один готовый MP3-файл.

После завершения обработки появится финальная версия записи. Её можно прослушать непосредственно в редакторе и при необходимости проверить результат перед сохранением.

Здесь же отображается длительность исходной записи, длительность готового файла, сколько времени было удалено при монтаже, а также размер готового MP3.

Готовый файл можно скачать на устройство.

Кроме того, финальную версию можно сохранить в Аудиоархиве портала Мэсэр. Для этого сначала должен быть сохранён текущий проект обработки.

Как сохраняются проекты, финальные версии и исходные записи и как затем открыть их с другого устройства, будет показано в следующей части.

# Часть 3. Аудиоархив

Теперь перейдём к Аудиоархиву.

Использовать Аудиоархив необязательно. Например, если нужно просто отредактировать запись на том устройстве, где доступны её файлы, и быстро получить результат для скачивания.

Но если требуется дополнительная гибкость и мобильность в работе служащего либо разделение задач между служащими, Аудиоархив будет максимально полезен.

Он позволяет хранить исходные записи Zoom, результаты обработки и проекты спикерских непосредственно на портале Мэсэр.

Это, в частности, позволяет передавать работу между служащими и продолжать её с другого устройства.

Например, один служащий получил запись Zoom с отдельными дорожками участников, а обработкой записи будет заниматься другой.

Вместо того чтобы отдельно пересылать ему все файлы, первый служащий может сохранить исходные дорожки в Аудиоархиве. После этого другой служащий сможет открыть эту же запись непосредственно через портал Мэсэр.

Другой возможный сценарий — служащий загрузил файлы сразу после записи с одного компьютера, а через несколько дней продолжил работу над ними с другого.

Чтобы добавить новую запись в Архив, используется кнопка «Создать запись».

Сначала указывается название записи.

При необходимости можно также указать дату и время собрания.

После этого выбираются исходные дорожки Zoom.

Если при выборе файлов какая-то дорожка была пропущена, её можно добавить с помощью кнопки «Добавить дорожки».

Если же были выбраны неправильные файлы, кнопка «Выбрать заново» позволяет заменить весь выбранный список.

До сохранения можно проверить список выбранных файлов и их общий размер.

После нажатия «Сохранить запись» исходные дорожки загружаются в Аудиоархив, и созданная запись становится доступна на портале.

Сохранить исходную запись в Аудиоархив можно не только непосредственно из самого Архива.

Если работа уже была начата в Аудиоредакторе с файлами, находящимися на устройстве, там также доступна кнопка «Сохранить запись Zoom в аудиоархив».

Таким образом, нет необходимости заранее решать, понадобится ли вам Архив. Можно начать обычную обработку локальных файлов, а при необходимости сохранить исходную запись в Архив уже в процессе работы.

Работает это и в обратную сторону.

Уже сохранённую запись можно открыть в Аудиоредакторе прямо из Аудиоархива.

Для этого нужно открыть нужную запись. В разделе «Что сделать с этой записью?» доступны два варианта: подготовить её для анонса или обработать спикерскую.

Кнопка «Открыть анонс-мейкер» открывает эту запись в соответствующем режиме Аудиоредактора.

Для спикерской, если проект обработки ещё не создавался, используется «Начать обработку». Если же сохранённый проект уже существует, вместо этого будет предложено «Продолжить обработку».

Есть и другой путь: находясь непосредственно в Аудиоредакторе, можно выбрать вариант «Из аудиоархива», найти нужную запись и открыть её оттуда.

В обоих случаях используются сохранённые в Архиве исходные дорожки, поэтому повторно загружать их с устройства не требуется.

## Результаты для анонс-мейкера

После обработки записи в режиме «Анонс-мейкер» готовый MP3 можно не только скачать на устройство, но и сохранить в Аудиоархиве.

Сохранённый результат остаётся связан с той же исходной записью Zoom и отображается внутри неё как отдельная версия для анонс-мейкера.

Если позднее эту же запись обработать ещё раз — например, выбрать другой состав дорожек или получить новый результат, — его можно сохранить как следующую версию.

Предыдущая версия при этом не заменяется и остаётся доступной в Архиве.

Таким образом, у одной исходной записи может храниться несколько готовых версий для анонс-мейкера.

Каждую из них позже можно прослушать или скачать непосредственно из Аудиоархива.

## Проект спикерской

В режиме «Спикерская» в Аудиоархиве можно сохранить не только готовый MP3, но и сам проект обработки.

Проект хранит текущее состояние работы: установленные границы начала и конца записи, вырезанные участки, участки тишины на отдельных дорожках, исключённые из готовой версии дорожки и выбранные настройки обработки звука.

Сохранённый проект можно позже снова открыть и продолжить работу с того же места.
Например, если в записи слишком много проблематичных мест на одной из дорожек, либо было несколько случаев разрыва связи, которые нужно вырезать полностью из всех дорожек, обработку можно разделить на несколько сеансов, всякий раз сохраняя новое состояние проекта.

При этом исходные дорожки загружаются из Аудиоархива вместе с сохранёнными настройками и правками, поэтому повторно выбирать файлы на устройстве не требуется.

Если работа была начата с локальных файлов и исходная Zoom-запись ещё не сохранена в Архиве, при первом сохранении проекта будет предложено сохранить одновременно и исходные дорожки, и сам проект.

Каждое новое сохранение проекта создаёт новое состояние в его истории.

Предыдущие состояния при этом не перезаписываются и остаются доступными.

Поэтому при необходимости можно открыть более раннее состояние проекта и продолжить работу уже от него.

Это может быть полезно, например, если после нескольких изменений вы решили вернуться к одному из предыдущих вариантов монтажа.

## Финальные версии спикерской

После завершения обработки спикерской готовый MP3 можно скачать на устройство или сохранить в Аудиоархиве как финальную версию.

Каждая такая версия остаётся связана с конкретным сохранённым состоянием проекта, из которого она была создана.

Это означает, что если позже продолжить работу над проектом и внести новые изменения, уже сохранённая финальная версия не изменится.

После новых правок можно сохранить очередное состояние проекта, снова создать готовый MP3 и сохранить его как следующую финальную версию спикерской.

Таким образом, в Аудиоархиве могут одновременно храниться несколько готовых версий одной и той же спикерской, созданных на разных этапах работы.

Каждую сохранённую версию можно прослушать или скачать непосредственно из Аудиоархива.

Кроме того, при необходимости можно выбрать одну из финальных версий и продолжить редактирование именно с того состояния проекта, на основе которого она была создана.

## Как найти сохранённые материалы

Чтобы найти ранее сохранённую запись, в Аудиоархиве используется кнопка «Показать записи».

Запись можно найти по её названию или по имени одной из исходных дорожек. Также можно ограничить поиск определённым месяцем.

При необходимости доступны дополнительные фильтры — например, можно показать только записи, для которых сохранён проект спикерской, версии для анонс-мейкера или финальные версии спикерской.

После открытия нужной записи в одном месте доступны все связанные с ней материалы.

Здесь можно увидеть исходные дорожки, готовые версии для анонс-мейкера и спикерской, а также сохранённый проект спикерской и историю его состояний.

Последние готовые версии доступны в разделе «Готовые записи».

Остальные сохранённые версии находятся в разделе «Все версии и управление».

История сохранений спикерской находится в разделе «Проект обработки спикерской».

Таким образом, все материалы, относящиеся к одному собранию, остаются связаны с одной исходной записью Zoom, и их не приходится искать отдельно в разных местах.

# Завершение

Итак, подведём итог.

Упомянутые инструменты позволяют существенно упростить работу с записями спикерских собраний.

Использование отдельных дорожек Zoom даёт возможность работать со звуком каждого участника отдельно и использовать одну и ту же исходную запись для разных задач.

Анонс-мейкер может получить более короткую запись на нужном языке, автоматически сократив длинные паузы.

В режиме «Спикерская» можно обработать звук отдельных участников, выполнить необходимый монтаж и создать готовую финальную запись.

А Аудиоархив позволяет сохранить исходные дорожки, результаты и проекты обработки, чтобы продолжить работу позже, с другого устройства или передать её другому служащему.

Эти возможности сделают подготовку записей спикерских собраний проще и удобнее.

# PART B · Approved Visual Direction

Предыдущий storyboard superseded. Новый storyboard должен быть построен заново по утверждённому сценарию PART A.

Обязательные решения:

1. **Никаких титров на чёрном фоне.**
   - Не использовать пустой чёрный экран как фон для названия ролика, названия части или промежуточного заголовка.
   - Заголовок смыслового блока должен быть встроен в текущую визуальную композицию или показан на отдельном, но содержательном и не чёрном переходном кадре.

2. **Инструкция делится на смысловые блоки.**
   - Каждый блок визуально отделяется от предыдущего.
   - В начале блока показывается его короткий заголовок.
   - Граница блока должна совпадать с естественной смысловой границей в narration, а не с произвольным таймингом.

3. **Озвучка не должна спешить.**
   - Не уплотнять речь ради сокращения общей длительности.
   - Между законченными мыслями и при переходе к новому смысловому блоку оставлять естественную паузу.
   - Внутри длинных абзацев разрешается дополнительное сценовое деление без изменения текста.
   - Визуал должен успевать показать действие до перехода к следующей мысли.

4. **Конкретный интерфейс показывать реальным интерфейсом Meser.**
   - Если narration говорит о конкретной кнопке, меню, окне, дорожке, секции, фильтре или состоянии, показывать соответствующий реальный UI.
   - Абстрактную графику использовать прежде всего для объяснения концепций, которые нельзя ясно показать одним реальным UI-состоянием.

5. **Курсор и акцентирование должны помогать понимать действие.**
   - Курсор подъезжает к значимой области перед действием.
   - Клики должны быть визуально читаемы.
   - Активную секцию, окно, дорожку или область можно дополнительно выделять.
   - Когда прежняя позиция курсора перестаёт иметь смысл после перехода/склейки, курсор скрывается и появляется уже у следующей значимой цели.

6. **Не допускать случайного мелькания кадров и визуально непонятных склеек.**
   - Переходы должны сохранять понятный контекст.
   - Не показывать короткие промежуточные UI-состояния только потому, что они возникли во время автоматизации.

7. **Новый visual pass должен быть спроектирован после утверждённого narration.**
   - Старые generated candidates можно использовать как reference/evidence, но не как финальную композицию.
   - До нового полного render сначала подготовить новый semantic storyboard и shot plan.

# PART C · Visual Concepts That Still Need Explicit Coverage

Формат каждой сцены должен быть выбран заново при storyboard pass. Ниже перечислены концепции, которые narration требует объяснить визуально; этот список не задаёт старую композицию кадров.

1. **Zoom multitrack** — один общий файл против отдельных синхронизированных дорожек.
2. **Анонс-мейкер / сокращение пауз** — дорожка нужного языка и сокращение длинной общей тишины.
3. **Несколько переводчиков** — сохранение речи, если сигнал есть хотя бы на одной выбранной дорожке.
4. **Speaker per-track processing** — отдельная обработка участника без воздействия на остальные дорожки.
5. **Solo / Mute / исключение из микса** — явно показать различие между мониторингом и финальным результатом.
6. **Timeline navigation** — горизонтальный масштаб, Fit, высота дорожек, Follow и Loop.
7. **Монтаж** — tool-first механика «Вырезать» / «Тишина», draggable «Начало» / «Конец», изменение и снятие правок.
8. **Project vs final** — сохранённое состояние проекта не равно готовому MP3; финальная версия связана с конкретным состоянием.
9. **Archive hierarchy** — одна Zoom-запись связывает исходники, проекты, историю и готовые версии.
10. **Cross-device / handoff** — сохранение в Архив позволяет продолжить работу позже или другому служащему.

# PART D · On-screen Text Policy

Экранный текст должен поддерживать narration, а не заменять его.

Разрешено:
- короткие заголовки смысловых блоков;
- названия реальных UI-элементов;
- короткие поясняющие подписи, если без них действие трудно понять;
- краткие различия вроде «Только прослушивание» и «Влияет на финальный результат».

Не использовать:
- чёрные standalone title cards;
- длинные абзацы поверх видео;
- технические титры, которые narration не требует и которые отвлекают от текущего действия;
- дублирование целых предложений narration на экране.

# PART E · Content Rules for Automation

1. PART A не менять семантически и не перефразировать без явного утверждения пользователя.
2. Разрешается разбивать PART A на большее число сцен ради спокойного темпа и визуальной понятности.
3. Browser scene должна показывать реальный интерфейс Meser, когда речь идёт о конкретной функции интерфейса.
4. Все демонстрационные данные synthetic.
5. В production Archive ничего не записывать, не изменять и не удалять.
6. Не использовать старый storyboard как автоматический источник shot order.
7. Не использовать black-screen title cards.
8. Каждый смысловой блок должен иметь видимый заголовок и визуально понятную границу.
9. TTS pacing должен следовать смыслу текста; запрещено ускорять narration только ради целевой длительности.
10. «Вырезать» показывать с фактической tool-first механикой и возможностью «Снять вырез».
11. «Тишина» показывать с фактической tool-first механикой и возможностью «Снять тишину».
12. «Начало» / «Конец» показывать как перетаскиваемые маркеры, а не как действие после предварительного выделения.
13. Solo и Mute показывать как функции только для прослушивания.
14. «Исключить из микса» показывать как изменение финального результата без удаления исходной дорожки.
15. Обязательно различать:
    - Сохранить проект;
    - Создать финальную версию;
    - Скачать MP3;
    - Сохранить финальную версию в Архив.
16. Анонс-мейкер всегда остаётся человеком/должностью. Обработку выполняет алгоритм.
17. Конкретные меню, окна, секции и состояния, названные в narration, визуализировать фактическим UI.
18. Курсор, клики и highlights использовать семантически; не сохранять курсор в старой позиции после смены контекста.
19. Не допускать коротких случайных flash-кадров между смысловыми сценами.
